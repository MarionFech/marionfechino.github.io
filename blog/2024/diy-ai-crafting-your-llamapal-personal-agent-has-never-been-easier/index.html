  1. Quantization: Optimizing Model Loading Efficiency

Quantization plays a pivotal role in optimizing the efficiency of our AI assistant. By reducing the numerical precision of the model’s weights, we can significantly decrease memory and computational requirements, making the model more efficient, especially on hardware with limited resources. However, it’s crucial to acknowledge that this optimization may also impact the model’s accuracy. There are several approaches to quantization.

Different options lie ahead of you, depending on the purpose and hardware limitations.

  • To begin, the essential library required is the Transformers package developed by Hugging Face. While this library allows for model loading, it’s important to note that the loaded model will not be compressed.
from transformers import AutoTokenizer
import transformers
import torch
tokenizer = AutoTokenizer.from_pretrained("meta-llama/Llama-2-7b-chat-hf")
pipeline = transformers.pipeline(
"text-generation",
model="meta-llama/Llama-2-7b-chat-hf",
torch_dtype=torch.float16,
device_map="auto",
)
  • You can also use sharding, a way to chunk into small pieces (depending on your limitations) the model you want to use. It can be done using the Accelerate library to keep the model in small pieces. However, to load the model, you would need to use the Fairscale library to load a model in shards for inference or training. Check the documentation for more information about the fully sharded data parallel method.
  • Then, you can use the BitsandBytes library, which will perform quantization on your model loading, changing the number of bits of memory used by the model. This powerful technique reduces the memory requirement to load a model without sacrificing its performance. You can check here for more technical details.
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM, BitsAndBytesConfig

model_id = "meta-llama/Llama-2-7b-chat-hf"
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_use_double_quant=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16
)

tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(model_id, quantization_config=bnb_config, device_map={"":0})
  • Finally, you can use post-quantization techniques such as GPTQ, auto-GPTQ, ANQ, or the GGUF method. Each one has its own pros and cons. The choice depends on the model you are using, your machine components (CPU, GPU, and GPU size), and the balance between compression and accuracy of the model that you want to keep.

GPTQ, tailored for GPT models, post-quantizes weights during fine-tuning. Choose between BitsAndBytes and GPTQ based on your specific needs: BitsAndBytes for general-purpose quantization in transformer models, and GPTQ for GPT-specific quantization. The auto-GPTQ library in Hugging Face’s transformers is suitable for large language models with encoder or decoder architectures like Llama, OPT, GPT-Neo, and GPT-NeoX. You can also find the implementation of auto-GPTQ for different models developed by The Bloke, who created more than 3000 implementations of different quantizations with other models. Additionally, ANQ (Action Weight Quantization) prioritizes significant weights based on activation and can be accessed through the vllm package. GGUP (GPT-Generated Unified Format) optimizes CPU usage by utilizing GPU only for specific layers to speed up the process, accessible via the transformers package.

Select your preferred model and load the suitable version, optimizing with the right quantization standard for compression/accuracy balance. Utilize a Hugging Face transformer pipeline: quantize, tokenize, and integrate into Langchain’s workflow efficiently.

pipeline = pipeline(
    task='text-generation',
    model=model,
    tokenizer=tokenizer,
    return_full_text=True,  # needed by langchain
    # model params
    max_new_tokens=512,
    temperature=0.1,  # creativity of responses: 0.0 none ->  1.0 max
    repetition_penalty=1.1  # to avoid repeating output
)

2. Embeddings: Personalizing the Model

You want to personalize your agent. At this step, you have two possibilities again. You can add documents (webpage, raw text, pdf*…) and transform those documents into embeddings that you will evaluate using an existing embedding space (here, all-mpnet-base-v2). You can then store those new data in a vector store. To do so, you need to charge the proper embeddings for your task, load your documents, tokenize them, and calculate them before charging the results using Faiss or Chroma.

from langchain.document_loaders import PyPDFLoader 
from langchain.text_splitter import RecursiveCharacterTextSplitter


pdf_path = "YourPDF.pdf"
documents =  PyPDFLoader(pdf_path).load_and_split()


#Cut your pdf file into smaller text chunks
text_splitter = RecursiveCharacterTextSplitter(
  chunk_size=1000,
  chunk_overlap=20
)

chunked_documents = text_splitter.split_documents(documents)
from langchain.embeddings import HuggingFaceEmbeddings
from langchain.vectorstores import FAISS

model_name = "sentence-transformers/all-mpnet-base-v2"
model_kwargs = {'device': 'cpu'}
encode_kwargs = {'normalize_embeddings': False}
embeddings = HuggingFaceEmbeddings(
    model_name=model_name,
    model_kwargs=model_kwargs,
    encode_kwargs=encode_kwargs
)
# storing embeddings in the vector store
vectorstore = FAISS.from_documents(texts, embeddings)

As it is the primary type that we will feed the model in the following article, here is a little glimpse of information concerning PDF reading and loading into an LLM. PDF reading poses challenges, with various packages available for tasks like decoding images into text. Errors in PDF interpretation can have significant consequences, particularly in sensitive contexts like financial summaries. 3. Alternative Fine-Tuning with LoRA

Consider using Parameter-Efficient Fine-Tuning (PEFT) for large pre-trained models. Traditional fine-tuning methods are costly due to the vast number of parameters. Instead, opt for techniques like low-rank adaptation (LoRA), which adapts a smaller subset of parameters, reducing the computational burden and overfitting risks. LoRA projects hidden states into a lower-dimensional space for adaptation before projecting them back. It enhances efficiency and performance across tasks like text classification and language translation for models like GPT-3.

from peft import prepare_model_for_kbit_training
from peft import LoraConfig, get_peft_model
from datasets import load_dataset

#Prepare the model for fine-tuning training with peft method
model.gradient_checkpointing_enable()
model = prepare_model_for_kbit_training(model)

def print_trainable_parameters(model):
    """
    Prints the number of trainable parameters in the model.
    """
    trainable_params = 0
    all_param = 0
    for _, param in model.named_parameters():
        all_param += param.numel()
        if param.requires_grad:
            trainable_params += param.numel()
    print(
        f"trainable params: {trainable_params} || all params: {all_param} || trainable%: {100 * trainable_params / all_param}"
    )


#Use LoRA
config = LoraConfig(
    r=8, 
    lora_alpha=32, 
    target_modules=["query_key_value"], 
    lora_dropout=0.05, 
    bias="none", 
    task_type="CAUSAL_LM"
)

model = get_peft_model(model, config)
print_trainable_parameters(model)

4. Conversational Retrieval Chain: Interactive Querying

A crucial aspect of any AI assistant is its ability to engage in meaningful conversations with users. Leveraging a conversational retrieval chain, we can enable our assistant to answer both model-based and embedding-based queries, providing comprehensive and relevant responses. This integration empowers users to interact with the assistant naturally and intuitively.

You can test your agent before deployment by using a Langchain conversational retriever chain that will use both the model and the embeddings to answer your question. Interestingly, the RAG retrieval generation model uses both retrieval-based and generative answers.

from langchain.chains import ConversationalRetrievalChain
from langchain import PromptTemplate
from langchain_core.prompts import ChatPromptTemplate

custom_template = """You work for CompanyX which sells things located in United States.
        If you don't know the answer, just say that you don't. Don't try to make up an answer.
        Base your questions only on the knowledge provided here. Do not use any outside knowledge.
        Given the following chat history and a follow up question, 
        rephrase the follow up question to be a standalone question, 
        in its original language.
        Chat History:
        {chat_history}
        Follow Up Input: {question}
        Standalone question:
      """
      
custom_prompt_from_template = PromptTemplate.from_template(custom_template)

memory = ConversationBufferMemory(memory_key="chat_history", input_key="question", return_messages=True)
    
chain = ConversationalRetrievalChain.from_llm(
  llm,
  vectorstore.as_retriever(),
  condense_question_prompt=custom_prompt_from_template,
  memory=memory,
  response_if_no_docs_found="I don't know"
)

Analyze prompts closely; they adhere to structured standards, unlike natural conversations. Adhering to these standards is essential for effective response from the model. There are some resources to automatically optimize prompts, such as APO (Automatic Prompt Optimization) or AutoPrompt.
